# Representative web exercise

This is a public synthetic consumer fixture, independent from neon1. The visitor is a developer deciding whether a task needs any Context guidance. They should find the native-sufficient route, a focused output/TDD selection with preview/use/refresh/undo commands, or a recurring loadout, then filter it and inspect a web verification checklist. No install or remote submission occurs.

Direction: a calm reading surface with strong type and divided catalogue rows. An expressive green/dark variant demonstrates explicit brand latitude without changing hierarchy. The compared alternatives were an identical-card landing page and a dense command console; the chosen reading surface makes the catalogue easier to compare and keeps guidance understandable.

Portal geometry lives in style.css: one system type family, a responsive heading scale, shared semantic surfaces and action colors, fluid spacing and clear focus. The fixture deliberately uses available system fonts for deterministic offline rendering and no font download or network request; upstream display-font taste is advisory. The previous quiet/expressive color-only palettes now map to shared Neon 1 Light/Matrix Dark through the existing Alternate colors shortcut. Appearance defaults to System and offers all six shared presets plus validated colors, radius and density. This changes the old temporary, nonpersistent shortcut into one persistent Context-only preference; it does not change layout, profiles, library choices or installation authority. The MIT @deep/theme candidate owns the palette and validation bytes; Monitoring supplies the adapted browser controller. Exact provenance is in docs/portal-appearance-source.json. No generated imagery or external requests are used.

Acceptance: built/static output, 320/390/768/1440px, all six shared presets and System, no overflow, clear keyboard focus/skip link, filter/empty/reset, disclosure, browser-local theme persistence, invalid/blocked storage, cross-tab reset, unchanged profile request export, reduced motion, axe, no browser errors, <=120 KB total delivered bytes (previous build limit 90 KB; unchanged shared module and adapter add about 25 KB). Viewport captures need visual inspection and a critique/revision pass. No claimed production CWV, human usefulness or assistive-technology approval.
