# Task context packs

Context can collect task source and explicitly selected Context guidance into a persistent preview. The operator chooses the Git project and task, reviews ranked candidates, adjusts by item ID, then exports a frozen text or JSON render. A preview ID can be reopened after process restart. Export checks the current source observations and rereads each bound tracked file; changed sources fail with `source_drift` and need a new scan.

Run the CLI from this checkout. The private store must be outside both the project and Context checkout:

```sh
python scripts/context_pack.py candidates --project /path/to/project --store /private/context-packs --task "change total pricing" --guidance guidance:core/testing.md
python scripts/context_pack.py candidates --project /path/to/project --store /private/context-packs --task "inspect invoice API" --focus src/invoice.py --representation structure
python scripts/context_pack.py candidates --project /path/to/project --store /private/context-packs --task "review module contract" --focus src/module.py --representation full
python scripts/context_pack.py preview --project /path/to/project --store /private/context-packs --candidates CANDIDATE_SET_ID --max-tokens 2000
python scripts/context_pack.py export --project /path/to/project --store /private/context-packs --preview PREVIEW_ID --format json
python scripts/context_pack.py reduce --project /path/to/project --store /private/context-packs --preview PREVIEW_ID --item SOURCE_ITEM_ID --max-lines 12
```

The Python entry point is `ContextPackService(project, *, store, context_root=..., project_id=...)`. Its `candidates(task, focus=(), guidance_ids=(), representation="excerpt")`, `preview(candidate_set_id, include_ids=None, exclude_ids=(), max_tokens=2000)`, and `export(preview_id, format="text")` methods accept configured source roots and saved IDs. Representation is a closed choice: `excerpt` preserves the existing exact-window behavior and output, `full` selects the complete bounded source, and `structure` selects a Python AST reading view or falls back to exact full text with a reason. The choice is frozen into the candidate set and replayed at export. `ContextPackError` exposes stable `code` and bounded `message` values.

`preview_pack_reduction(service, preview_id, item_id, max_lines=12)` (also the `reduce` CLI command) is a read-only preview over one exact, complete source already included in a frozen pack. It re-exports and verifies that pack first, and refuses guidance, excerpts, structural projections, missing items, or changed source. For source text of 50 or more physical lines it preserves the first and last two lines, then prioritizes error/failure lines and warnings within the explicit 8–100 line cap. Short and empty inputs pass through. Its returned segments cover the original text exactly using Unicode code-point offsets and distinguish kept, omitted, and cap-dropped ranges; inputs requiring more than 4,096 segments are refused. The estimate is UTF-8 bytes divided by four, rounded up; it is not a tokenizer result. The reduction is not saved, applied, or substituted into the frozen Context pack. It does not promise semantic equivalence or measured token savings.

The bounded severity-selection idea was informed by inspection of Headroom's pinned log compressor (`log_compressor.rs`, pin `3fef15d376d9899f77a28464e2e91f8b99514930`, Apache-2.0). No Headroom source or dependency is included; this implementation is a separate deterministic policy with explicit exact-span accounting.

All representations start from bounded UTF-8 bytes in tracked regular files allowed by the repository map's path policy. Excerpts remain exact windows of up to 40 complete source lines and 4,096 bytes. Full mode retains the complete source. Python structure mode uses `python-ast-segments-v1` to retain exact imports, module assignments, decorated class/function/method signatures, leading comments, and module/declaration docstrings. Each retained segment records original byte and line ranges plus its hash; omissions carry original line ranges and reasons. Text export labels each exact segment with its original lines and marks generated omission notes as presentation, not source. Structural output is lossy context, never executable or behavior-equivalent source. Unsupported languages, malformed/deep files, one-line declarations, unretained notices, and non-reducing results fall back to exact full text with a recorded reason. Focused files over the existing read/file budgets are omitted whole with an explicit reason. CRLF and missing final newlines are retained. Guidance IDs use `guidance:<registered-resource-path>` and resolve through Context's active dependency registry. Guidance, dependencies, support data and required source notices are carried as full bytes; guidance is advisory and never changes native instructions or permissions.

The store contains private, mode-0600 immutable JSON records inside a mode-0700 directory. It is bound to configured roots and project ID. Both complete wire formats are capped at four UTF-8 bytes per requested token; estimates are `ceil(bytes/4)`, not provider token counts. `--output` only creates a new file, outside both source trees. The filename/path exclusion policy is not secret detection; inspect any export before external delivery. No installation, model call, clipboard, upload or automatic agent delivery occurs.

The `ceil(bytes/4)` token count is an estimate and does not imply equal model-token savings. Unknown languages use the repository map's lexical declaration/reference scan; unsupported languages use exact fallback in structure mode. Binary or unreadable files are omitted with bounded diagnostics. See [provenance](context-pack-provenance.md) for the serializer adaptation and source-selection boundary.
