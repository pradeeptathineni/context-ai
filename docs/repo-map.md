# Repository map

`scripts/repo_map.py` builds an optional, read-only map for a task in an explicitly selected Git checkout. It reports relevant tracked paths, conservative symbol names and definition lines, selection reasons, each selected file's SHA-256, the observed HEAD and dirty state, and omissions. It does not read untracked files, copy source text, install guidance, invoke a model, or write to the target project.

```sh
python3 scripts/repo_map.py --project /path/to/checkout --task "change total pricing" --focus src/pricing --max-tokens 1200
python3 scripts/repo_map.py --project /path/to/checkout --task "change total pricing" --format json
```

The Python API is `build_map(project: Path, task: str, *, focus=(), max_tokens=2000) -> dict`. Focus paths are relative to the selected repository and select a file or subtree. Invalid or escaping paths fail. The map includes tracked regular files with a documented source/config/document extension allowlist; it skips binary and unsupported files, `.env`/secret/credential-like names, `.pem` and `.key` files, `secret(s)/` and `credential(s)/` path components, lockfiles, generated/vendor/cache directories, symlinks and submodules. This is a small filename/path policy, not universal secret detection. Limits are 5,000 tracked files, 256 KB per file and 8 MB total reads. Python symbols use the standard-library AST. Other file types use declaration and identifier patterns, so the map does not resolve calls or types. Malformed or over-deep Python is skipped with a diagnostic.

For deterministic static Python import dependents, see [import impact](import-impact.md). That view follows AST import statements and reports unresolved/ambiguous syntax and caps; it does not establish runtime loading.

`max_tokens` estimates the larger of the complete text and compact JSON output at four UTF-8 bytes per token; it is not a provider tokenizer guarantee. `estimated_tokens` includes headings and diagnostics, while `estimated_entry_tokens` covers entries. The task used for matching is capped at 2,048 characters and its displayed form at 120 characters. At most eight diagnostics are shown, each clipped to 64 characters, with a total warning count. The complete rendered text and JSON, including JSON escaping and the final newline, are capped at `max(4,096, 4 * max_tokens)` bytes; warning/task samples and then entries are shortened as needed while retaining omission counts. If metadata fits the byte ceiling but exceeds the requested token estimate, the map returns no entries and marks `budget_satisfied` false. If even bounded metadata cannot fit the hard byte ceiling, the API raises a short `MapError` rather than returning oversized output. `max_tokens` accepts values from 1 to 8,192. Compact JSON preserves `schema`, `head`, `dirty`, `task`, `entries`, `total_tokens`, `entry_tokens`, `limit` and `budget_ok`; entry digests use the key `sha256`, and omission counts are in `omissions`.

File reads use root-relative directory descriptors and no-follow opens at every path component. Pre-read, descriptor and post-read file identities must agree; every byte read, including discarded race reads, consumes the total limit. HEAD and index are checked again after scanning; a changed HEAD/index aborts the map. `dirty` reflects the final working-tree observation, `observation_changed` marks a status change during the scan, and `consistency` explicitly labels this as a non-atomic filesystem observation. A file digest describes the bytes read, not proof that they were at HEAD.

## Implementation choice and provenance

The user-visible capability is a compact, task-ranked file and symbol map. Context's existing `scripts/context_ai.py` owns pinned context selection and delivery, not repository mapping, so this remains an optional producer that consumers may pass to an agent explicitly. The implementation uses Python's standard library and deliberately avoids an index/cache or parser dependencies: bounded one-shot reads fit the current consumer contract and keep the target repository untouched.

The design was informed by Aider's `RepoMap` at [`5dc9490bb35f9729ef2c95d00a19ccd30c26339c`](https://github.com/Aider-AI/aider/tree/5dc9490bb35f9729ef2c95d00a19ccd30c26339c), specifically task-mentioned file/name personalization, weighted ranking and finite-budget selection. The inspected donor files were `aider/repomap.py` and `tests/basic/test_repomap.py`; its license was Apache-2.0. This implementation was written against the Context contract and does not copy donor source code or tests. The donor's disk cache, tree-sitter, networkx, Pygments and grep_ast stack is not needed for this bounded standard-library producer. The donor snapshot's maintenance status was not independently rechecked for this implementation.
