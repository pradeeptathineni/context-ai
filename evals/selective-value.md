## Local use

From the reviewed Context checkout with its source-local requirements installed:

```sh
# Ordinary one-off work: use the project's instructions and native tools directly.
# Optional recurring ownership without extra task guidance:
.venv/bin/python scripts/context_ai.py plan --project /absolute/consumer --provider both
.venv/bin/python scripts/context_ai.py apply --project /absolute/consumer --provider both
# A concrete verbose-output need:
.venv/bin/python scripts/context_ai.py plan --with context-output --project /absolute/consumer --provider both
.venv/bin/python scripts/context_ai.py apply --with context-output --project /absolute/consumer --provider both
.venv/bin/python scripts/context_ai.py verify --project /absolute/consumer
```

From the consumer directory, use `python3 .context-ai/resources/scripts/context_output.py run --log NEW_RAW_LOG -- COMMAND ...`, or `inspect RAW_LOG --query DISTINCTIVE_TERM`. Raw/status destinations must be new; a nonzero producer returns nonzero while the evidence remains available. `--start N --lines M` retrieves a range. Read the partial-view boundary before deciding omitted data is absent. Native redirection plus bounded search is also sufficient.

Refresh is a preview: `.venv/bin/python scripts/context_ai.py refresh --project /absolute/consumer`. Apply an approved selection at a task checkpoint. Stop with `.venv/bin/python scripts/context_ai.py undo --project /absolute/consumer`; unchanged owned guidance is removed, edited files and private logs are retained. No background runtime needs stopping. See [loadouts](../docs/loadouts.md) for interrupted-write recovery and portable ownership.
