# Browser verification

Source-supported tooling: [Playwright](https://playwright.dev/docs/test-snapshots) and [axe integration](https://playwright.dev/docs/accessibility-testing), reviewed 2026-10-05. Use the project's existing browser facilities or explicit scoped test dependencies; record unavailable tools rather than inventing results.

For an interaction failure, reproduce the state sequence before changing it: input, submit/navigation, edit/retry and reset. Preserve audience, content, brand and the existing stack. Read package manifests and candidate scripts as data before running authorized checks. A local Playwright package can be usable without a global CLI; declaration, installed files, browser launch and passed checks are distinct. Use already installed tooling; discovery must not run `npx`, package scripts or executable configuration.

Build and serve the distributed output. Test real navigation, focus, forms or relevant states, failure recovery, reduced motion and responsive widths. Capture and inspect desktop/mobile full-page screenshots. Review hierarchy, typography, density, overflow, footer and interaction states. Run a deliberate critique/revision pass and confirm affected checks. Fix relevant console/network errors and serious accessibility defects.

Assert the meaningful keyboard outcome (for example focus at the skip-link destination), rather than merely observing some element after several Tabs. Prefer [auto-waiting assertions](https://playwright.dev/docs/test-assertions) for asynchronous state. Retain a [trace](https://playwright.dev/docs/trace-viewer) or failure screenshot when it will explain a hard failure; keep raw artifacts local and summarize discriminating evidence. Operate the page through one suitable path: project-local Playwright for reproducible assertions/console/network/traces, or supported native host browser controls for observed interaction and screenshots. Native host availability is host-reported, independent of PATH; name any assertion/trace gap and do not silently claim equivalent coverage.

Keep screenshots, interaction/axe findings, build/asset observations and changes attributable to review. Distinguish visual judgment, deterministic results, builder proxy and human approval. No screenshot-diff baseline is visual approval; no fixture proves a private production website.
